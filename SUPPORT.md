# Support

OpenClaude uses GitHub Discussions, GitHub Issues, and the security policy for different kinds of help. Choosing the right path keeps maintainers from turning support requests into unsupported release, production, public, external-validation, or autonomous-reliability claims.

## Where to Ask

- Use [GitHub Discussions](https://github.com/Gitlawb/openclaude/discussions) for setup help, provider configuration questions, idea exploration, and general community conversation.
- Use [GitHub Issues](https://github.com/Gitlawb/openclaude/issues) for confirmed bugs with reproduction steps, environment details, and local evidence.
- Use [SECURITY.md](SECURITY.md) for private vulnerability reports. Do not open a public issue for an unpatched vulnerability.
- Use [CONTRIBUTING.md](CONTRIBUTING.md) before opening a pull request.
- Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) in project spaces.

## What to Include

- OpenClaude version and install path.
- OS, terminal, shell, and runtime versions.
- Provider/model path if relevant, with secrets redacted.
- Exact local command output or report paths when available.
- Whether the issue reproduces without provider/live model calls.
- Screenshots only when useful, with credentials and private paths redacted.

## Privacy and Safety

Do not post API keys, tokens, cookies, credentials, private profiles, raw user/session payloads, or private local repository content. Summaries, hashes, and redacted snippets are preferred.

Support responses are best-effort community guidance. They do not authorize deploy, publish, launch, production OpenClaude mutation, MFH mutation, real product repo mutation, canonical memory/governance write, canonical decision ledger write, mth resolution, external validation claims, public readiness claims, release readiness claims, production readiness claims, autonomous reliability claims, provider-backed execution claims, or live model validation claims.
