# Mimesis Engineering

Status: active operating frame
Date: 2026-06-14

## Definition

Mimesis Engineering is the Metaforge practice of improving agent work by absorbing the load-bearing structure of proven artifacts.

It is not persona prompting. It does not ask an agent to "act like an expert." It extracts what experts, products, papers, standards, patents, and working repositories actually do, then turns those structures into local prompts, policies, tests, gates, and evidence records.

## Product Role

Mimesis Engineering is the infinite-improvement loop for Metaforge:

```text
Source scout
-> Structure extraction
-> Local adaptation
-> Orchestra execution
-> MFH evidence gate
-> Meta memory and decision update
-> Continue, shrink, expand, or stop
```

This gives Metaforge a marketable but proof-bounded claim:

> Metaforge does not rely on agent self-confidence. It imports the operating grammar of proven systems and keeps only what survives local evidence gates.

## Operating Rules

1. Start from local repo truth.
2. Pull primary sources before making architecture or marketing claims.
3. Prefer maintained open source, official docs, papers, patents, standards, and verified local artifacts.
4. Extract structure, not branding:
   - decision criteria
   - failure detectors
   - invariants
   - data flow
   - verification oracle
   - permission boundary
   - provenance shape
5. Adapt the structure into a small Metaforge artifact.
6. Run a non-LLM or bounded verification gate when possible.
7. Record what the evidence proves and what it does not prove.
8. Turn mimesis off when the naked baseline already reaches the objective ceiling or when a borrowed structure is harmful.

## What Gets Absorbed

| Source class | What to extract | What not to copy |
| --- | --- | --- |
| Product docs | workflow grammar, user-facing constraints, approval boundaries | brand claims, logos, proprietary wording |
| Open-source repos | architecture seams, tests, failure handling, adapter surfaces | unreviewed dependency adoption or license-risk code |
| Papers | experimental design, task loop, memory/eval pattern | benchmark claims outside the tested setting |
| Patents | prior-art shape, workflow risk, approval pattern vocabulary | claim language, ownership, freedom-to-operate assumptions |
| Standards | control vocabulary, provenance model, security requirements | compliance claims without assessment |
| Local best work | taste, decision path, failure detectors, acceptance criteria | nostalgia or unverified "it felt better" claims |

## Metaforge Mapping

| Metaforge layer | Mimesis responsibility |
| --- | --- |
| Meta | Stores source ledgers, decisions, rejected sources, and owner taste boundaries |
| Goal Kernel | Requires research requirements, claim boundaries, validation commands, and non-goals |
| Orchestra | Dispatches independent scouts and critics so context stays protected |
| MFH | Blocks closure when evidence, state, source reconciliation, or claim boundary is weak |
| OpenClaude runtime | Provides local tools, OAuth-backed model routes, file edits, tests, and reports |

## Claim Boundary

Allowed now:

- Metaforge uses a source-first Mimesis Engineering loop.
- Mimesis Engineering is a working operating frame for extracting structure from proven artifacts.
- Current evidence is local, repo-bound, and partially experimental.
- Some Mimesis gates have local scripts and case notes in the private workbench.

Not allowed yet:

- Industry-standard claim.
- Production-readiness claim.
- External validation claim.
- Legal freedom-to-operate claim.
- SLSA/NIST/OWASP/OAuth compliance claim.
- Claim that mimesis always improves model output.
