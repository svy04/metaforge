## Redaction Rules

| Rule | Action | Applies To | Reason |
| --- | --- | --- | --- |
| `credentials_and_tokens` | `omit` | API keys, OAuth tokens, cookies, private keys, authorization headers | Trace reports must never become credential stores. |
| `provider_request_identifiers` | `omit` | Provider request IDs, message IDs, run IDs, and raw error correlation IDs | Provider correlation identifiers are unnecessary for product-quality summaries. |
| `raw_prompt_and_completion_payloads` | `count_only` | Raw prompt text, raw completion text, raw tool observations, and raw provider errors | Quality gates need counts, roles, status transitions, and hashes rather than sensitive payload bodies. |
| `local_path_and_environment_details` | `bounded_label_only` | Home directories, profile paths, environment variables, and machine-specific runtime details | Reports should preserve reproducibility without leaking local operator context. |
| `raw_trace_identity` | `hash` | Raw local trace files | SHA-256 preserves artifact identity while avoiding raw-line publication. |

## Capture Workflow

1. Capture non-synthetic user/session traces only after an explicit operator action selects the session and local file path.
2. Store raw JSONL only under the local reports/orchestra-*.jsonl pattern; do not copy credentials, provider configs, profiles, caches, databases, cookies, or environment files.
3. Run bun run product:real-trace-evals to produce structured summaries with hashes, counts, roles, models, query sources, and status transitions.
4. Run bun run product:trace-redaction-policy to scan raw traces for credential and provider-request-id patterns before any report is treated as publishable evidence.
5. Publish only docs/product-quality summary reports; keep raw provider payloads, raw prompt/completion text, authorization data, and local environment details out of reports.
6. If any credential pattern is detected, stop the product-quality gate and quarantine the trace outside publishable evidence until the operator resolves it.
